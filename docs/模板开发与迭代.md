# 创建自己的模板与持续更新

## 使用内置模板

Skill 读取已确认的本机标准、选定版本的 controls/recipe，再将本期素材与时间绑定到原生工程。字体写入 story.fontFamily；字幕、音乐、音效与速度按用户标准编排。保存草稿、检查预览，再通过工作台导出。

## 自建模板

可以让 Codex 或具备本地执行能力的 WorkBuddy 在本机源码上协助创建。先建立新ID，不覆盖内置模板，例如：

```sh
node scripts/create-user-template.mjs my-method 我的方法讲解 team.yanye-faceless
```

脚本在 user-templates/my-method/0.1.0 下复制基础模板规范，生成独立manifest，初始为development，不展示给成品模板中心。这个目录默认不进Git，不会随作者升级覆盖。已有同名版本时拒绝覆盖。

修改 controls/recipe 中可支持的参数，按基础渲染器创建工程并测试；runtimeTemplate 指明实际渲染器合同，目录中的自建ID只是发现与版本标识。增加全新版式或新动画需要修改/增加源码渲染器及校验、测试，不能仅改manifest就宣称新增渲染能力。字体自定义支持三个制作模板；其他参数按模板现有合同落实。

验收完成后，在manifest将releaseChannel改为production并填写明确的description、预览入口及验证范围；运行 node scripts/template-catalog.mjs。刷新模板中心，会自动读取发布目录，不再手改页面的固定卡片列表。development、learning-reference和候选版本不可发布为production。预览图需使用自己的可分发素材。

## 作者持续发版

作者本地研究库与GitHub发行目录保持独立，只有验收后的制作模板进入 templates/<系列>/<版本>/。添加新版本manifest并设置releaseChannel=production，保留旧工程需要的兼容实现；独立新渲染器须附代码和验证。生成目录、构建、测试、预览检查后，再发布新的GitHub tag与完整包、Skill包和校验值。固定版本的旧工程不自动改为新模板。

多个版本均为production时会列出多个版本入口，用户须按版本选择；退役版本改为archived，运行时兼容源码可保留。更新不得删除用户标准、user-templates或媒体和草稿。

## 用户升级

新版解压到独立目录，停止旧服务并备份。迁移 media、drafts、exports、user-data 和 user-templates，保留媒体编号；重建目录，再安装依赖。不要以程序包覆盖旧配置。跨不同渲染合同的旧工程应先验证，不承诺任意版本永久兼容。

完成测试后可运行 `python3 scripts/package-release.py 版本号 输出目录`。该工具仅打包发行仓库源码与production模板，排除用户标准、自建私有模板、媒体、草稿、Git与依赖，生成完整包、Skill包和校验值。包内文件清单也随版本更新；本工具不能替代人工版权和内容审查。
